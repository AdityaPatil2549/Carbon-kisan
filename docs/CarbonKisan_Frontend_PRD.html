Carbon Estimator
The core differentiator. Practice → area → live SHAP-explained estimate. Try it — click a practice, drag the slider.
Components
PracticeSelectorSliderShapBreakdownChartButtonErrorBanner
Key interactions
  • Practice card selection is required before "Get estimate" enables (button stays disabled, not hidden — PRD copy principle: never punish exploration)
  • Area slider updates a live hectare label on every drag frame, not just on release
  • Form state persists to localStorage on every field change (FR-12.1) — a dropped connection mid-flow never loses farmer input
  • SHAP breakdown bars animate in sequentially (80ms stagger) on estimate arrival — the one deliberate motion moment on this screen

States & error copy standards

Per the product's writing principle: errors don't apologize and are never vague. Every error below names what happened and what to do.

Error copy — approved vs rejected

Situation✕ Don't write✓ Write instead
Estimate API fails"Oops! Something went wrong.""Couldn't reach the server. Check your connection and try again."
Price outside allowed band"Invalid price""Price must be within 40% of ₹2,148 — try between ₹1,289 and ₹3,007."
Duplicate payment webhook"Error 409""This purchase was already completed. Check your email for the certificate."
Empty marketplace filter result"No results found""No listings match these filters yet. Try widening your price range or district."
Session expired mid-form"Unauthorized""Your session expired. Your entries are saved — log in again to continue."

Loading pattern decision table

SituationPatternWhy
Estimate calculation (<800ms target)Button spinner, not skeletonSub-second — a skeleton would flash and feel broken
Marketplace listing gridSkeleton cards (3-6 grey placeholders)Content shape is known in advance — skeleton sets accurate expectation
Impact dashboard first loadSkeleton stat cardsSame reasoning — known shape, variable content
Certificate PDF generationDeterminate progress text ("Generating certificate…")Has a real multi-second duration the user should feel is progressing, not stuck
